1. Vue d'ensemble — Ecosysteme JADOMI Sante

Principe fondamental
Le patient ne paye JAMAIS. Tout est gratuit pour le patient. Toujours. Zero exception.
Le professionnel de sante paye un abonnement mensuel. JADOMI est l'infrastructure.

1.1 Les 3 couches de l'ecosysteme

COUCHE 1 — LE PRO (paye) Dentiste (9-49 EUR/mois) | Infirmiere (9-49 EUR/mois) | Kine | Medecin | ... → Stock, Documents, Signature, Facturation, Communication, Analytics COUCHE 2 — LE PATIENT (gratuit) App PWA jadomi.fr/patient → Voit ses RDV, recoit les notifications push, ajoute ses pros de sante → Le patient pousse ses autres pros a rejoindre (boucle virale) COUCHE 3 — LES FOURNISSEURS (commission) Fabricants + Revendeurs + Pharmacies → Proposent produits/equipement au groupage → JADOMI prend 10% de commission

IDE s'abonne → dit au patient "telecharger JADOMI" → Patient telecharge (GRATUIT) → Patient voit: "ajoutez votre dentiste, kine, medecin..." → Patient pousse ses autres pros → Nouveaux pros s'abonnent → Ils poussent LEURS patients... → Croissance exponentielle sans pub

2.2 SOS Urgence Confreres — Architecture

SOS Urgence — Zero commission, adoption virale
Le dentiste deborde appuie sur un bouton → les confreres a proximite (30km) recoivent une notification push → le premier qui accepte recoit le patient. JADOMI ne prend ZERO commission. C'est le service gratuit qui fait adopter la plateforme par tous les dentistes de la zone.

Flux technique

1. Dr Bahmed → POST /api/sos-urgence/create { type: "douleur_aigue", initiales: "M.D.", quartier: "Roubaix centre" } 2. Server → SELECT societes WHERE type='cabinet_dentaire' AND distance < 30km → Trouve 8 cabinets dans le rayon 3. Server → INSERT sos_urgence_notifications (1 par cabinet) → Push notification a chaque cabinet 4. Dr Leroy recoit notification → voit dans son onglet SOS Urgence → Clique "J'accepte" 5. Server → PATCH request.status = 'accepted' → Email a Dr Bahmed: "Dr Leroy a accepte votre urgence" → Coordonnees echangees

Tables SQL

sos_urgence_notificationsrequest_id FK, target_societe_id, status (sent/seen/accepted/declined)

3.2 Feature 1 — Placement automatique patient

KILLER FEATURE — Le patient appelle, le systeme le place
Un patient appelle pour un soin. L'IDE tape son nom + adresse. Le systeme calcule instantanement le meilleur creneau dans la tournee du jour pour minimiser le detour. "Mme Dupont, 12 rue Voltaire ? Je vous propose 10h15, c'est entre mes 2 patients de votre quartier."

Algorithme

POST /api/ide/patient/place { patient_name: "Dupont", address: "12 rue Voltaire, Roubaix", soins: "pansement" } 1. Geocoder l'adresse → latitude/longitude (API Nominatim/Google) 2. Pour chaque creneau possible dans la tournee du jour: a. Inserer le patient entre visite[i] et visite[i+1] b. Calculer le detour: distance(visite[i] → nouveau) + distance(nouveau → visite[i+1]) - distance(visite[i] → visite[i+1]) c. Ajouter la duree estimee du soin 3. Trier par detour minimal 4. Retourner les 3 meilleurs creneaux: → "10h15 — detour 0.8 km (entre M. Martin et Mme Legrand)" → "11h30 — detour 1.2 km (entre Mme Petit et M. Robert)" → "14h00 — tournee soir, detour 0.3 km (optimal)" 5. L'IDE choisit → le patient est insere → tournee recalculee

3.3 Feature 2 — Split Matin/Soir

Deux tournees, un patient vu 2 fois
Mme Dupont a besoin d'insuline le matin ET d'un pansement le soir. Elle apparait dans les 2 tournees automatiquement. Chaque tournee est optimisee independamment.

Modele de donnees

ide_recurrences: patient: Mme Dupont soins_type: "insuline" tournee_pref: "matin" jours_semaine: [lun, mar, mer, jeu, ven, sam, dim] ide_recurrences: patient: Mme Dupont soins_type: "pansement mollet" tournee_pref: "soir" jours_semaine: [lun, mer, ven] → Genere automatiquement les visites dans les 2 tournees → Chaque tournee optimisee separement → Possibilite: matin = Alice, soir = Bob (multi-IDE)

3.4 Feature 3 — Multi-IDE collaboratif

Cabinet "IDE Roubaix Sud" — 3 infirmieres: Alice (couleur: bleu) → 18 patients matin + 12 patients soir Bob (couleur: vert) → 15 patients matin + 14 patients soir Claire (couleur: orange) → 20 patients matin + 10 patients soir Vue admin (la titulaire): → Voit les 3 tournees superposees sur une carte → Drag & drop un patient d'Alice vers Bob → recalcul instantane → Equilibrage automatique: "Alice a 8 km de plus que Bob, deplacer M. Martin?" Vue individuelle (chaque IDE): → Voit SA tournee du jour uniquement → Navigation GPS en 1 clic vers le prochain patient → Bouton "Je suis arrivee" → push au patient + horodatage

3.5 Feature 4 — Tracking Uber

Le patient voit l'infirmiere approcher en temps reel
Push gratuit: "Marie arrive dans 8 minutes" avec position sur la carte. La personne agee ne guette plus a la fenetre. Les aidants/famille peuvent aussi suivre.

Architecture technique

1. L'IDE appuie "En route" sur sa PWA → PATCH /api/ide/visit/:id/status { status: 'en_route' } → Sa position GPS est partagee (navigator.geolocation.watchPosition) 2. Le serveur recoit la position toutes les 30 secondes → Calcule ETA via distance restante / vitesse moyenne 3. Push notification au patient: → "Marie arrive dans 8 minutes" → Mise a jour toutes les 2 minutes 4. L'IDE arrive → appuie "Arrivee" → Push: "Marie est arrivee" → Horodatage automatique dans le dossier Cout: ZERO (push PWA gratuit, GPS natif navigateur)

3.6 Feature 5 — Confirmation automatique veille

Chaque soir a 19h, CRON automatique: 1. Pour chaque patient du lendemain: → Push app: "Votre infirmiere Marie passe demain vers 8h15. OK ? / Annuler" 2. Le patient repond: → OK → rien a faire → Annuler → la visite est supprimee 3. A 22h, reoptimisation automatique: → Les annulations sont retirees → La tournee est recalculee → Nouvelle tournee prete pour le lendemain matin 4. L'IDE se reveille → ouvre l'app → tournee a jour, zero coup de fil

3.7 Feature 6 — Dictee vocale IA

L'IDE a les mains occupees (pansement, perfusion). Elle appuie sur le micro: "Pansement mollet gauche change, exsudat modere, bonne cicatrisation, prochaine refection mercredi" → Web Speech API (gratuit, natif navigateur) → Transcription texte → Claude IA structure les donnees: { soin: "pansement", localisation: "mollet gauche", observation: "exsudat modere, bonne cicatrisation", prochain_rdv: "mercredi" } → Insert dans le dossier patient Gain estime: 45 min/jour de saisie en moins

3.8 Feature 7 — Remplacement instantane

Alice est malade lundi matin: 1. Alice appuie "Je suis absente" dans l'app → POST /api/ide/absence { date_debut: lundi, date_fin: lundi } 2. Le systeme redistribue ses 18 patients: a. D'abord aux collegues du cabinet (Bob, Claire) b. Recalcule les 2 tournees avec les patients en plus c. Si surcharge → diffuse aux IDE JADOMI a proximite (comme Uber) 3. Push notifications: → Aux collegues: "Alice est absente, 6 patients ajoutes a votre tournee" → Aux patients d'Alice: "Votre infirmiere de remplacement est Bob" → A Alice: "Vos patients sont pris en charge par Bob et Claire" 4. Tout est automatique. Zero coup de fil.

3.9 Feature 8 — Pharmacie connectee

L'IDE voit que Mme Dupont n'a plus de compresses: 1. Dans l'app, bouton "Commander a la pharmacie" → Selectionne les produits necessaires → Envoie la commande a la pharmacie du quartier du patient 2. La pharmacie recoit la notification → Prepare la commande → "Pret dans 2h" 3. L'IDE repasse ou le patient va chercher Revenue JADOMI: commission sur chaque commande pharmacie → Nouveau canal de revenus sans effort

3.10 Feature 9 — Alerte ordonnance

Le systeme detecte automatiquement: "L'ordonnance de M. Martin expire dans 3 jours. 0 seance restante sur la prescription de 30 seances." → Push au patient: "Prenez RDV chez votre medecin pour le renouvellement" → Notification a l'IDE: "M. Martin — ordonnance expire le 02/05" L'IDE ne perd plus de patients par oubli d'ordonnance. Le medecin prescripteur recoit un rappel (si inscrit sur JADOMI).
