01. Vision et problème

JADOMI ne remplace PAS les logiciels existants. JADOMI crée une couche intelligente au-dessus de tous les outils du cabinet.

Le problème

Un cabinet dentaire utilise en moyenne 12 à 18 outils séparés :

📧

Communication

Mails (Gmail, Outlook, Yahoo), SMS patients, WhatsApp, Doctolib messagerie

📅

Agenda

Doctolib, Google Calendar, agenda logiciel de gestion, planning remplacement

💻

Logiciel de gestion

Logos_w, Julie, Visiodent, Desmos — télétransmission CPAM, fiches patient, FSE

📷

Imagerie

Caméra intra-orale, CBCT, radio panoramique, scanner STL, microscope

📄

Documents

Factures PDF, devis, ordonnances, certificats, courriers spécialistes

💰

Finance

Comptabilité, banque, fournisseurs, laboratoire prothèse, mutuelle

Constat : Tout est fragmenté. Aucun outil ne comprend le contexte global du cabinet. Le praticien perd 1h30/jour en tâches administratives qui pourraient être automatisées ou assistées.

La solution JADOMI

Un assistant IA intelligent qui comprend le contexte du cabinet, lit les mails autorisés, retrouve les documents, prépare les réponses, génère des tâches, et connecte les différents flux.

Inspirations : Notion AI (mémoire + recherche), Microsoft Copilot (Office), Claude Connectors (intégrations), Slack AI (résumés), ClickUp AI (tâches). Mais spécialisé cabinets dentaires/médicaux.

Flux de données principal

  1. Capture — Le Desktop Agent surveille les dossiers, capture les PDF/STL/images, fait l'OCR local
  2. Sync — Les données sont chiffrées et envoyées au Cloud via WebSocket/HTTPS
  3. Intelligence — Le Cabinet Brain indexe, classifie, et enrichit (IA multi-niveaux)
  4. Action — Le Task Engine génère des tâches, le Mail Copilot prépare des réponses
  5. Restitution — Le Dashboard affiche résumés, alertes, et suggestions au praticien

03. JADOMI Desktop Agent

Application légère installée sur le PC du cabinet. Tourne en arrière-plan, icône dans la barre système.

Choix technologique : Tauri v2

Critère Tauri v2 Electron Flutter Desktop
Taille binaire ~8 MB ~150 MB ~25 MB
RAM au repos ~30 MB ~150 MB ~80 MB
Accès filesystem natif Natif Rust Node.js Plugins
Sécurité Sandbox Rust Node.js complet Moyen
Auto-update Intégré Intégré Manuel
App mobile partagée v2 (Android/iOS) Non Natif
Recommandation : Tauri v2 pour le Desktop Agent (léger, sécurisé, Rust natif pour file watcher + OCR). Flutter reste pour l'app mobile patient/praticien (déjà codée). Pas de conflit : 2 apps, 2 contextes.

Modules du Desktop Agent

File Watcher

Surveillance de dossiers configurés (Documents, Téléchargements, export Logos_w). Détection nouveaux fichiers par polling + notify (crate Rust). Filtres : PDF, STL, OBJ, PLY, DICOM, JPG/PNG, XLSX, CSV.

OCR Local

Tesseract (via leptess crate Rust) pour extraction texte hors-ligne. Aucune donnée patient ne quitte le PC pour l'OCR. Enrichissement IA côté cloud après anonymisation.

Connector Bridge

Pont vers les logiciels locaux : lecture base Firebird (Logos_w), lecture exports CSV/XML (Julie, Visiodent), interception fichiers caméra. Mode read-only strict — jamais d'écriture dans le logiciel source.

Sync Engine

File d'attente locale (SQLite) + sync cloud via HTTPS/WebSocket. Chiffrement AES-256-GCM avant envoi. Reprise sur coupure. Delta sync (ne renvoie que les changements).

Tray UI

Icône barre système avec statut sync (vert/orange/rouge). Menu : Ouvrir dashboard, Paramètres, Dossiers surveillés, Pause/Reprendre, Déconnexion. Mini-fenêtre WebView pour les notifications.

Auto-Updater

Mise à jour silencieuse via Tauri updater intégré. Vérification signature RSA du binaire. Rollback automatique si crash post-update.

05. JADOMI Cabinet Brain

Mémoire structurée et évolutive du cabinet. Le Brain apprend progressivement les habitudes, les préférences, et le contexte de chaque cabinet.

Modèle de données Brain

cabinet_brain (table principale — 1 row par cabinet) ├── id (uuid, PK) ├── societe_id (FK → societes) ├── identity JSONB # SIRET, TVA, RPPS, n° Ordre, banque... ├── team JSONB # salariés, rôles, horaires, congés ├── contacts JSONB # comptable, banque, avocat, assureur... ├── preferences JSONB # règles mails, ton, workflows... ├── workflows JSONB[] # séquences automatisées apprises ├── updated_at timestamp cabinet_brain_documents (index des documents du cabinet) ├── id (uuid, PK) ├── societe_id (FK) ├── source (enum: desktop_agent, mail, upload, scan, connector) ├── type (enum: facture, devis, ordonnance, certificat, contrat, stl, radio, photo, courrier, autre) ├── title text ├── content_text text # OCR / extraction texte ├── metadata JSONB # montant, TVA, fournisseur, patient, date_doc... ├── embedding vector(1536) # pgvector pour recherche sémantique ├── storage_path text # chemin R2 ou local ├── checksum text # SHA-256 intégrité ├── indexed_at timestamp cabinet_brain_events (journal d'événements — apprentissage) ├── id (uuid, PK) ├── societe_id (FK) ├── event_type text # mail_received, document_filed, task_created... ├── context JSONB # qui, quoi, quand, résultat ├── user_action text # ce que l'utilisateur a fait (correction Brain) ├── created_at timestamp cabinet_brain_rules (règles apprises / configurées) ├── id (uuid, PK) ├── societe_id (FK) ├── category text # mail, compta, agenda, fournisseur, patient... ├── rule_text text # "Mails comptables → ton professionnel" ├── conditions JSONB # quand appliquer ├── actions JSONB # que faire ├── confidence float # 0.0 → 1.0 (apprise vs configurée) ├── source text # 'user_configured' | 'learned' | 'default' ├── active boolean

Comment le Brain apprend

BOUCLE D'APPRENTISSAGE CABINET BRAIN 1. OBSERVATION Le Brain observe les actions de l'utilisateur : → Mail classé dans "Comptabilité" → le Brain retient le pattern → Document renommé de "scan_001" → "Facture GACD mars 2026" → Tâche créée manuellement après réception d'un mail fournisseur 2. EXTRACTION DE PATTERN IA (Mistral Small, coût ~0€) analyse les séquences répétées : → "Chaque facture GACD est classée en Comptabilité" → "Chaque mail du comptable reçoit une réponse sous 24h" → "Le lundi matin, le Dr vérifie toujours les mails banque en premier" 3. PROPOSITION DE REGLE Le Brain propose : "Voulez-vous que je classe automatiquement les factures GACD en Comptabilité ?" → Oui → règle créée (confidence: 1.0, source: 'user_configured') → Non → pattern noté mais pas de règle (confidence: 0.3) 4. APPLICATION Les règles validées s'appliquent automatiquement. Les règles apprises (confidence > 0.7) s'appliquent avec notification. Les règles incertaines (confidence < 0.7) → suggestion uniquement. 5. CORRECTION Si l'utilisateur corrige une action automatique : → confidence baisse de 0.2 → Si < 0.3 → règle désactivée → Le Brain ne refait plus la même erreur

Exemples de règles Brain

Catégorie Règle Action Source
Mail Mail du comptable M. Dupont Ton professionnel, joindre docs si disponibles, ne jamais valider un montant seul Configurée
Compta Facture fournisseur > 500€ Créer tâche "Vérifier montant" + notifier Configurée
Agenda Patient Mme Martin annule souvent le vendredi Suggérer créneau mardi/mercredi pour elle Apprise
Fournisseur GACD livre toujours le mardi Planifier commande le lundi soir Apprise
Document STL reçu du labo Classer dans dossier patient + notifier praticien Configurée

Recherche intelligente

Le Brain permet une recherche en langage naturel sur tous les documents et données du cabinet :

Exemples de recherches Brain : "Facture GACD de mars" → Recherche hybride : full-text (trigram) + sémantique (pgvector) → Résultat : Facture GACD n° 2026-0342, 1 245,80€ HT "Combien on a dépensé chez Henry Schein ce trimestre ?" → Agrégation SQL + réponse IA formatée → Résultat : 3 847,20€ HT (T1 2026), +12% vs T4 2025 "Le patient qui avait un problème de bridge la semaine dernière" → Recherche sémantique sur notes cliniques + agenda → Résultat : M. Leroy, 14 mai, descellement bridge 36-37 "Envoie la facture du labo au comptable" → Intent detection + action : retrouve la dernière facture labo, prépare le mail au comptable, attend validation

06. JADOMI Mail Copilot

Assistant mail intelligent connecté via OAuth sécurisé. Lit, classifie, prépare, mais ne décide jamais seul pour les sujets sensibles.

Workflow OAuth sécurisé

FLUX OAUTH — CONNEXION MAIL 1. Praticien clique "Connecter ma messagerie" dans JADOMI │ 2. Redirection vers Google/Microsoft/Yahoo OAuth │ (scope limité : lecture seule + envoi, PAS gestion compte) │ 3. Praticien autorise JADOMI sur son compte │ 4. OAuth retourne un authorization code │ 5. JADOMI échange le code contre access_token + refresh_token │ Tokens stockés chiffrés (AES-256) en base │ refresh_token permet de renouveler sans re-login │ 6. JADOMI lit les mails via IMAP (Google: imap.gmail.com:993) │ ou API REST (Microsoft Graph, Gmail API) │ JAMAIS de stockage de mot de passe utilisateur. JAMAIS d'accès au-delà des scopes demandés. L'utilisateur peut révoquer l'accès à tout moment.

Scopes OAuth demandés

Provider Scopes Ce que ça permet
Gmail gmail.readonly + gmail.send Lire mails + envoyer (avec validation)
Outlook Mail.Read + Mail.Send Idem Microsoft Graph API
Yahoo mail-r + mail-w Lecture + envoi IMAP OAuth

08. Système d'agents IA

Architecture multi-agents spécialisés, orchestrés par le Brain, avec optimisation de coûts à 3 niveaux.

Router IA (existant, à enrichir)

ROUTER IA — 3 NIVEAUX DE COUT Niveau 1 — GRATUIT (instant) ├── Moteur de règles local (regex, lookup tables) ├── Classification d'intent (compromise.js + natural.js) ├── Détection actes dentaires (FDI, CCAM) ├── Alertes médicales (AVK, bisphosphonates) └── Templates de réponse pré-configurés Niveau 2 — LOW-COST (1-5s) ├── Ollama local Qwen 2.5:14B (0€, extraction structurée) ├── Mistral Small API (0.13€/M tokens, chat/classif) ├── Mistral Pixtral (0.13€/M, vision/OCR) └── DeepSeek Chat (0.14€/M, catalogues) Niveau 3 — PREMIUM (2-15s) ├── Claude Sonnet (3€/M, documents complexes, génération) └── GPT-4o (2.5€/M, Whisper transcription) REGLE : Toujours essayer Niveau 1, puis 2, puis 3. Objectif : 80% des requêtes traitées en Niveau 1-2 (coût ~0€).

Agents spécialisés

Agent Classifieur

Niveau 1-2
Classifie les mails, documents, et événements. Utilise d'abord des règles (expéditeur connu → catégorie), puis IA si ambiguïté.

Agent Extracteur

Niveau 2
Extrait données structurées des PDF : montants, TVA, références, dates. OCR local (Tesseract) + enrichissement Mistral Pixtral.

Agent Rédacteur

Niveau 2-3
Génère brouillons de réponse mail, certificats, courriers. Respecte le ton configuré par le Brain (professionnel, chaleureux...).

Agent Planificateur

Niveau 1-2
Gère les tâches, les rappels, les deadlines. Détection automatique des dates dans les mails et documents.

Agent Comptable

Niveau 2
Rapprochement factures/commandes, alertes écarts, préparation exports comptable (FEC, Factur-X).

Agent Sécurité

Toujours actif
Sanitise PII avant envoi IA externe (Data Guard). Vérifie les règles RGPD/HDS. Audit trail.

Règles IA et données de santé

  • JAMAIS de données patient identifiantes envoyées à une IA externe (Claude, Mistral, DeepSeek)
  • Data Guard scrub AVANT chaque appel IA externe : noms, NIR, RPPS, dates de naissance
  • Ollama local pour les données sensibles (0 fuite, 0 coût)
  • DeepSeek = catalogues produits UNIQUEMENT (jamais données santé)
  • Logs IA purgés après 90 jours (configurable)
  • Le patient peut demander l'export et la suppression de ses données (RGPD art. 17)

Migration HDS

Prévu : Migration vers serveur certifié HDS (OVH Healthcare / Scaleway HDS). Devis OVH reçu. Obligatoire dès qu'on stocke des données de santé à caractère personnel. En attendant, les données de santé restent dans Supabase (chiffrées) avec RLS strict.

15. Recommandations réalistes

Stratégie de développement

1. Brain d'abord, Desktop ensuite

Construire le Brain + Mail Copilot côté web avant le Desktop Agent. Le web est testable immédiatement. Le Desktop Agent est un canal de capture supplémentaire — il ajoute de la valeur mais n'est pas bloquant pour le MVP.

2. Votre cabinet = premier beta

Tester sur vous-même pendant 2 semaines avant d'ouvrir. Connecter votre Gmail, votre Logos_w, vos dossiers. Le Brain apprend VOS habitudes → product-market fit garanti.

3. OAuth Gmail en premier

Gmail est le plus simple (documentation Google excellente, librairie googleapis). Outlook (Microsoft Graph) en second. Yahoo déjà en partie fait (OAuth tokens en base).

4. Pas de Redis/BullMQ au MVP

node-cron + EventEmitter suffisent pour 1 à 50 cabinets. Redis quand le volume le justifie (> 50 cabinets, > 10K mails/jour). Éviter la complexité prématurée.

5. Tauri v2, pas Electron

Tauri = 8 MB vs 150 MB Electron. Rust = sécurité + performances. Tauri v2 supporte mobile (Android/iOS) en bonus. Le frontend peut être du HTML/CSS/JS simple (pas besoin de React).

6. HDS dès que possible

Migrer vers serveur certifié HDS avant d'accepter des données de santé de tiers. Pour votre propre cabinet c'est toléré, mais pour du SaaS multi-cabinets c'est obligatoire. OVH Healthcare ou Scaleway HDS.
